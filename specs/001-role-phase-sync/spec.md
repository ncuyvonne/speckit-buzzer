## Clarifications

### Session 2026-11-10

- Q: 老師重新整理頁面或斷線重連後，應如何恢復老師操作權限？ → A: 短暫斷線重連保留老師權限；重新整理後須重新輸入密碼。（已由 Q3 修訂）
- Q: 老師斷線後，多久內重新連線才算「短暫」，可以保留老師權限？ → A: 60 秒內重連可保留權限；超過 60 秒後須重新輸入密碼。（已由 Q3 修訂）
- Q: 要我保留憲章規則，並把 001 改為老師每次重連都重新輸入密碼嗎？ → A: 老師每次斷線重連或重新整理頁面後，都須重新輸入密碼；取消 60 秒內免重新驗證的規則。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 老師登入並推進活動階段 (Priority: P1)

老師使用老師密碼進入老師操作畫面，依序將活動從「準備中」切換至「搶答中」，再切換至「已結束」。輸入錯誤密碼時，老師能看見清楚的錯誤訊息，且不會取得老師操作權限。每次斷線重連或重新整理頁面後，老師都須再次輸入密碼。

**Why this priority**: 老師是階段控制者；沒有可驗證的老師身分及階段控制，活動無法開始或結束。

**Independent Test**: 以正確密碼完成登入並逐步推進兩個階段；另以錯誤密碼確認登入被拒絕且畫面提供可理解的錯誤訊息。

**Acceptance Scenarios**:

1. **Given** 活動處於「準備中」且使用者尚未取得老師權限，**When** 使用者輸入正確的老師密碼，**Then** 系統授予老師操作權限並顯示目前階段與階段控制功能。
2. **Given** 使用者尚未取得老師權限，**When** 使用者輸入錯誤或空白密碼，**Then** 系統拒絕老師權限並顯示清楚的錯誤訊息。
3. **Given** 老師已登入且活動處於「準備中」，**When** 老師切換至下一階段，**Then** 活動進入「搶答中」。
4. **Given** 老師已登入且活動處於「搶答中」，**When** 老師切換至下一階段，**Then** 活動進入「已結束」。
5. **Given** 老師已登入且伺服器仍保有同一次活動（包含「已結束」階段），**When** 同一瀏覽器在任何斷線時長後重新連線，**Then** 系統要求重新輸入老師密碼，驗證成功後才恢復老師權限並顯示伺服器目前階段。
6. **Given** 老師已登入且活動處於任一階段（包含「已結束」），**When** 老師重新整理頁面，**Then** 系統要求重新輸入老師密碼，驗證成功後才恢復老師權限並顯示伺服器目前階段。

### User Story 2 - 學生選擇組別並同步看到活動階段 (Priority: P1)

學生進入活動後選擇有效組別，並在自己的畫面看到目前活動階段。老師切換階段後，所有已連線的老師與學生畫面都顯示相同階段。

**Why this priority**: 學生需要知道目前是否可以參與活動；一致的階段資訊可避免不同組別依據不同狀態行動。

**Independent Test**: 讓老師及至少兩位不同組別的學生同時加入，依序切換活動階段，逐一確認各畫面呈現同一階段。

**Acceptance Scenarios**:

1. **Given** 活動處於「準備中」，**When** 學生進入並選擇有效組別，**Then** 系統將學生識別為該組學生並顯示目前「準備中」階段。
2. **Given** 老師與多位學生已連線，**When** 老師切換活動階段，**Then** 所有已連線使用者的畫面更新為同一目前階段。
3. **Given** 學生選擇不在本次活動有效組別清單中的組別，**When** 學生提交選擇，**Then** 系統拒絕該選擇並指出如何選擇有效組別。
4. **Given** 同一組別已有其他學生在線，**When** 新學生選擇同一組別加入，**Then** 系統允許該學生以相同組別身分加入，不覆蓋其他學生的連線。

---

### User Story 3 - 學生重新整理或重新連線後恢復活動狀態 (Priority: P2)

學生在同一瀏覽器分頁選定組別後，只要同一次活動仍在伺服器記憶體中，重新整理頁面或在任何斷線時長後重新連線，系統都會恢復其原選組別並顯示活動目前階段；此規則包含「已結束」階段。

**Why this priority**: 網路中斷或頁面重整不應迫使學生重新選組，也不應讓學生看到過期階段。

**Independent Test**: 學生選定組別後，分別在「準備中」、「搶答中」及「已結束」重整或重新連線，確認恢復的組別與階段正確。

**Acceptance Scenarios**:

1. **Given** 學生已選擇組別且同一次活動仍由伺服器執行（包括「已結束」階段），**When** 學生重新整理頁面，**Then** 系統恢復該組別並顯示活動目前階段。
2. **Given** 學生已在同一瀏覽器分頁選擇組別且連線中斷，**When** 該分頁在同一次活動仍由伺服器執行時重新連線（不受斷線時長限制），**Then** 系統恢復該組別並同步活動目前階段。
3. **Given** 學生首次進入且沒有先前選擇的組別，**When** 活動尚未開始，**Then** 系統顯示「準備中」並要求學生選擇有效組別。

### Edge Cases

- 老師密碼錯誤、空白或尚未設定時，不得授予老師操作權限，並顯示清楚錯誤。
- 老師密碼不得出現在登入錯誤訊息或 log 中，也不得存放於程式碼、一般文件或版本庫。
- 活動尚未開始時學生進入，須顯示「準備中」；不可顯示過期階段。
- 同一組別的多位學生可以同時在線，各自重新整理或重連時仍恢復為該組別。
- 學生在每一個活動階段斷線後重連，都須取得伺服器目前階段，而非斷線前的舊階段。
- 未授權使用者嘗試切換階段，或老師嘗試略過／倒退階段時，系統須拒絕操作並提供錯誤訊息；活動階段保持不變。
- 老師每次斷線重連（不論斷線多久）及重新整理頁面後，都須重新輸入密碼才能操作。
- 學生提交無效或未選擇的組別時，系統須拒絕加入並提供修正方式。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 提供老師與學生兩種使用者角色；老師須以老師密碼取得老師操作權限。
- **FR-002**: 系統 MUST 拒絕錯誤、空白或未設定的老師密碼，且 MUST 顯示清楚錯誤訊息；拒絕後不得授予老師操作權限。
- **FR-003**: 老師密碼 MUST 由環境變數提供，且 MUST NOT 寫入程式碼、一般文件、log 或版本庫；錯誤訊息與 log MUST NOT 揭露密碼值。
- **FR-004**: 系統 MUST 支援「準備中」→「搶答中」→「已結束」三個活動階段，並只允許已授權老師依序推進階段。
- **FR-005**: 系統 MUST 以伺服器保存的目前階段作為唯一權威狀態；用戶端提供的階段值不得覆蓋伺服器狀態。
- **FR-006**: 老師切換階段後，所有已連線使用者 MUST 收到並顯示同一目前階段。
- **FR-007**: 學生 MUST 能在進入活動時選擇有效組別；系統 MUST 允許同組多位學生同時在線，且不得因其中一位加入或離線而變更其他學生的組別。
- **FR-008**: 在同一次活動仍於伺服器執行期間，學生從同一瀏覽器分頁重新整理或於任何時長的斷線後重連，系統 MUST 恢復該分頁原選組別，並顯示伺服器目前階段（包括「已結束」）；若該分頁沒有有效已選組別，系統 MUST 要求學生選擇組別。
- **FR-009**: 系統 MUST 驗證組別選擇及階段切換是否符合有效組別清單與目前伺服器階段；無效操作 MUST 被拒絕、保持共享狀態不變，並提供清楚且不洩漏機敏資料的修正訊息。
- **FR-010**: 本功能 MUST 僅支援在本機執行的課堂活動範圍；答案送出、題目匯入、搶答順位、計分及結果匯出不屬於本功能範圍。
- **FR-011**: 在同一次活動的任一階段（包含「已結束」），老師每次斷線重連或重新整理頁面後，系統 MUST 要求重新輸入老師密碼。驗證成功後才恢復老師權限並顯示伺服器目前階段。階段推進仍須符合 FR-004。

### Key Entities *(include if data involved)*

- **使用者**：參與活動的人，具有老師或學生角色及目前連線狀態。
- **老師憑證**：用來驗證老師身分的機敏資料；不得出現在可供使用者讀取的錯誤訊息或 log 中。
- **組別**：學生加入活動時選擇的有效參與單位；同一組別可同時有多位學生在線。
- **活動**：包含有效組別清單及目前階段的一次課堂搶答活動。
- **活動階段**：活動目前處於「準備中」、「搶答中」或「已結束」的狀態，只能由老師依序推進。
- **使用者連線**：使用者與活動的即時連線；學生重新整理或重連後須恢復組別並重新取得目前階段。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 正確密碼的老師可在一次操作流程內取得老師權限；錯誤、空白或未設定密碼的登入在 100% 驗收案例中均不取得老師權限。
- **SC-002**: 在一位老師與至少兩位不同組別學生同時連線的驗收情境中，每次階段切換後，所有在線畫面在 2 秒內顯示相同階段。
- **SC-003**: 學生在同一瀏覽器分頁、同一次活動的三種階段分別重整或重新連線時，100% 驗收案例均恢復正確組別並顯示當下階段。
- **SC-004**: 同組多位學生同時加入、離線或重新連線的驗收案例中，所有學生仍保有正確組別，且互不覆蓋。
- **SC-005**: 無效組別、未授權階段操作及不允許的階段跳轉在 100% 驗收案例中均被拒絕，活動狀態不因此改變，且使用者能辨識如何修正。
- **SC-006**: 在任一活動階段（包含「已結束」），老師於任何斷線時長後重連或重新整理頁面時，100% 驗收案例均須重新通過密碼驗證才能恢復老師權限，且驗證成功後均顯示伺服器目前階段。

## Assumptions

- 本機執行環境中會預先提供有效的老師密碼及本次活動的有效組別清單；組別清單以逗號分隔，解析時去除每項前後空白，並拒絕空項、重複項及含控制字元的項目；組別 ID 其餘內容視為不透明字串。本功能不包含建立、修改或管理組別清單的介面。
- 活動每次從「準備中」開始，老師只能依序推進至「搶答中」及「已結束」，不支援跳階或倒退。
- 學生在同一瀏覽器分頁的組別選擇，在同一次仍於伺服器執行的活動中，可於頁面重整及任何時長的斷線後恢復，且包括「已結束」階段。伺服器程序重新啟動會建立新的「準備中」活動；跨分頁、跨活動的身分管理與恢復保證不在本功能範圍。
- 階段同步的 2 秒驗收門檻適用於本機網路及正常連線情況；斷線期間不保證畫面即時更新，重連後須恢復正確狀態。
- 老師密碼遵循憲章，由環境變數提供；登入方法、有效組別及活動資料的具體儲存方式留待規劃階段決定。
