## Clarifications

### Session 2026-11-22

- Q: 活動結束後，老師執行「重設」時，Feature 006 應如何處理目前學習單與已提交的答案？ → A: 新增教師重設操作，回到「準備中」；保留目前學習單與題目，清除本場答案、鎖定狀態、成功結果、正誤標記與分數，並將時限設回 0 秒。
- Q: 老師執行活動重設時，是否應先確認再清除本場作答與計分結果？ → A: 顯示確認提示，說明保留學習單與題目、清除本場作答與計分資料並將時限歸零；老師確認後才重設，取消時活動資料不變。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 設定限時並公平結束搶答 (Priority: P1)

老師可在準備中設定每場搶答的秒數。開始後，老師與學生都能看到剩餘時間；期限到達時活動自動結束，逾時答案不會改變任何作答結果。

**Why this priority**: 明確的作答期限與一致的截止判定是課堂限時搶答的核心規則。

**Independent Test**: 設定 1 秒時限並開始搶答，觀察兩端倒數及自動結束；在截止前、正好截止及截止後送出有效答案，確認只有截止前收到的答案可被接受。另以 0 秒確認搶答不會自動結束。

**Acceptance Scenarios**:

1. **Given** 活動在「準備中」，**When** 老師設定 0、1 或 3600 秒，**Then** 系統接受設定；0 顯示為不限時。
2. **Given** 活動在「準備中」，**When** 老師輸入負數、大於 3600 或非整數秒數，**Then** 系統拒絕設定並說明允許範圍，活動設定不變。
3. **Given** 已設定大於 0 的時限，**When** 老師開始搶答，**Then** 倒數立即開始，師生畫面顯示剩餘秒數，並在期限到達時自動進入「已結束」。
4. **Given** 有效答案在期限前送達，**When** 系統判定答案，**Then** 該答案依既有搶答規則參與接受與成功組別判定。
5. **Given** 有效答案在期限時刻或之後送達，**When** 系統判定答案，**Then** 系統拒絕答案且不改變已接受答案、成功組別或作答進度。
6. **Given** 搶答倒數尚未歸零，**When** 老師手動結束活動，**Then** 活動立即結束、倒數停止，之後的計時到期事件及答案提交都不會改變活動結果。

### User Story 2 - 標記成功答案並查看計分板 (Priority: P1)

活動結束後，老師可為每題的成功組別人工標記「對」或「錯」，也可更改或取消標記。系統依標記計分並列出計分板；學生在活動結束後也能查看。

**Why this priority**: 老師負責判斷答案正誤，計分板提供透明且可修正的活動結果。

**Independent Test**: 建立多題且有不同成功組別的活動並結束；由老師標記、改標及取消判定，確認分數重算和排序；以學生身分確認結束後可看到相同計分板，且系統沒有自行判答。

**Acceptance Scenarios**:

1. **Given** 活動已結束且某題有成功組別，**When** 老師標記「對」，**Then** 該組得 1 分且計分板更新。
2. **Given** 活動已結束且某題有成功組別，**When** 老師標記「錯」，**Then** 該組該題得 0 分；系統不以答案文字自行改判。
3. **Given** 某題已有標記，**When** 老師改為另一判定或取消標記，**Then** 該題只保留最新標記（取消後為未標記），總分按最新狀態重新計算，不重複加分。
4. **Given** 題目沒有成功組別，或活動尚未結束，**When** 老師嘗試標記，**Then** 系統拒絕操作且計分板不變。
5. **Given** 活動已結束，**When** 老師新增、修改或取消正誤標記，**Then** 老師及已連線學生看到依最新標記計算的計分板。
6. **Given** 活動已結束並有正誤標記，**When** 老師或學生查看計分板，**Then** 所有組別依得分由高至低、成功題數由多至少、組別編號由小至大排列；相同組別不重複出現。
7. **Given** 活動已結束，**When** 老師選擇重設，**Then** 系統先說明會保留的學習單與題目、將清除的本場作答與計分資料，以及時限會歸零。
8. **Given** 老師看到重設確認提示，**When** 老師確認，**Then** 活動回到「準備中」、保留目前學習單與題目、清除所有作答、鎖定、成功結果、正誤標記及分數，並將時限設為 0 秒。
9. **Given** 老師看到重設確認提示，**When** 老師取消，**Then** 活動階段、學習單、答案、成功結果、標記、分數及時限均維持不變。
10. **Given** 老師已重設活動，**When** 老師成功重新匯入另一份學習單，**Then** 新題目取代舊題目且沒有舊作答、正誤標記或分數；若匯入失敗，現有學習單與題目維持不變。

### User Story 3 - 查看本組作答進度 (Priority: P2)

搶答進行中，學生可查看本組已送出的題數與活動總題數。此進度只反映本組已成功送出的題目，不顯示其他組別的任何作答資訊。

**Why this priority**: 本組進度讓學生知道尚有多少題可作答，同時保留搶答期間的組別資訊隔離。

**Independent Test**: 匯入含單題與題組的學習單，讓本組成功送出答案並檢查 N；確認每個題組只計 1 題，無效或逾時提交不增加 N，且其他組提交不改變本組提示。

**Acceptance Scenarios**:

1. **Given** 活動正在搶答中且本組尚未送出任何答案，**When** 學生查看畫面，**Then** 顯示「本組已送出 0 / 總題數」。
2. **Given** 本組已成功送出若干單題及題組答案，**When** 學生查看進度，**Then** N 等於本組已成功送出的不同題目數，每個題組只計 1 題。
3. **Given** 本組送出無效、被拒絕或逾時的答案，**When** 系統拒絕該答案，**Then** N 不增加。
4. **Given** 活動處於「準備中」或「已結束」，**When** 學生查看畫面，**Then** 不顯示搶答中的 N / 總題數提示；「已結束」時仍可查看計分板。
5. **Given** 其他組別提交答案，**When** 本組學生檢視進度或收到更新，**Then** 只更新本組數字，不顯示或可推知其他組別的作答內容或進度。

### Edge Cases

- 時限 0 表示不限時；1 與 3600 為有效邊界，-1、3601、小數及非數字輸入均拒絕。
- 倒數進行中老師手動結束時，活動立即結束且尚未到期的計時不再生效。
- 答案在截止前收到才可接受；收到時間恰等於截止時間或較晚時一律拒絕，即使倒數歸零與送出幾乎同時發生。
- 倒數到期後，即使畫面尚未完成更新，逾時提交也不得被接受。
- 手動結束前已接受的答案與成功組別保留；結束後不再接受新答案。
- 同題沒有成功組別時不可標記；題目有成功組別時，標記只針對該成功組別。
- 「對」改成「錯」時須減去原先取得的 1 分；改成「對」時只加 1 分；取消標記時移除該題原有得分。
- 成功題數依該組成為成功組別的不同題目數計算，不因標記為「錯」或取消正誤標記而減少。
- 同分時先比較成功題數；前兩項仍同分時依組別編號決定唯一順序。所有已設定組別均列入計分板，包括 0 分且沒有成功題目的組別。
- 題組完整答案算一次送出的一題；重複、無效或逾時答案不增加 N。
- 老師重設活動時保留學習單與題目，但清除本場答案、鎖定、成功結果、正誤標記與分數，並回到「準備中」及 0 秒時限。
- 老師取消重設確認時，不改變活動階段、學習單、作答、計分或時限。
- 成功重新匯入學習單會取代目前題目並清除舊活動結果；失敗的匯入不得部分清除或替換目前活動資料。
- 重新匯入後題數可能改變，新的作答進度總題數以成功匯入後的題目數為準。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 允許老師在「準備中」設定搶答時限，單位為整數秒，範圍包含 0 至 3600。0 MUST 表示不限時；新活動預設時限 MUST 為 0。系統 MUST 拒絕範圍外及非整數值，並指出可修正的範圍。
- **FR-002**: 設定時限大於 0 時，系統 MUST 在活動進入「搶答中」時開始倒數，並讓老師及學生畫面顯示剩餘時間；時限為 0 時，畫面 MUST 明確表示不限時而不顯示遞減的倒數秒數。
- **FR-003**: 系統 MUST 以權威的活動接收時間判定時限；期限前收到且符合既有規則的答案可被接受，期限時刻或之後收到的答案 MUST 一律拒絕。逾時拒絕 MUST NOT 建立作答、鎖定該組該題、變更成功組別或增加學生端進度。
- **FR-004**: 時限到達時，系統 MUST 自動將活動由「搶答中」結束；逾時答案即使在結束畫面更新前送達仍 MUST 被拒絕。結束時 MUST 停止倒數並通知連線中的師生畫面。
- **FR-005**: 老師在倒數歸零前手動結束時，系統 MUST 立即結束活動及停止倒數；手動結束前已接受的答案及成功組別 MUST 保留，結束後的答案提交 MUST 被拒絕，後續計時到期事件 MUST NOT 再次改變活動。
- **FR-006**: 系統 MUST 只允許老師在「已結束」後標記正誤，且只允許對有成功組別的題目標記。標記對象 MUST 為該題成功組別的答案；沒有成功組別的題目不可標記。
- **FR-007**: 每題 MUST 可標記為「對」、「錯」或未標記；老師可將既有標記改為另一值或取消。更新標記 MUST 取代舊值而非新增第二筆判定。系統 MUST NOT 依答案內容自動判斷正誤。
- **FR-008**: 系統 MUST 對每個「對」標記計 1 分；「錯」及未標記計 0 分。總分 MUST 隨標記新增、修改或取消即時重新計算，且每題最多貢獻 1 分。
- **FR-009**: 系統 MUST 為每組計算成功題數，即該組成為成功組別的不同題目數；成功題數不得因該題標記錯誤或取消標記而改變。計分板 MUST 包含目前名冊中的所有組別，包括 0 分組別。
- **FR-010**: 計分板 MUST 依得分降冪、成功題數降冪、組別編號升冪的順序排列。若組別編號是數字字串，MUST 依數值升冪排序（例如 2 排在 10 前）；其他組別識別碼 MUST 依自然字串順序排列，以產生唯一且穩定的結果。
- **FR-011**: 活動「已結束」後，老師及學生 MUST 都能查看計分板；每次新增、修改或取消正誤標記後，連線中的老師及學生 MUST 能看到更新後的計分板。學生可見的計分板至少包含排名、組別編號、得分及成功題數，且 MUST 繼續遵守既有學生答案可見範圍。
- **FR-012**: 學生端 MUST 只在「搶答中」顯示「本組已送出 N / 總題數」。N MUST 等於本組已被接受答案的不同題目數；題組作答視為一題，無效、重複或逾時的答案不計入 N。總題數 MUST 等於目前成功匯入的主題數。
- **FR-013**: 學生端進度提示及其更新 MUST 僅含本組作答題數與總題數，不得包含其他組別的提交狀態、答案、成功題數、得分或其他可推知上述資料的內容；準備中與已結束時 MUST 隱藏該進度提示。
- **FR-014**: 系統 MUST 允許老師在活動「已結束」後選擇重設，並在執行前顯示確認提示，列明會保留目前學習單與題目、清除本場所有答案、鎖定、成功結果、正誤標記及分數，且時限會歸零。老師確認後，活動 MUST 回到「準備中」並執行上述清除；老師取消時，活動階段及所有資料 MUST 維持不變。學習單成功重新匯入並取代目前題目時，系統 MUST 清除所有舊活動作答與計分資料；匯入失敗時 MUST 保留現有活動資料且不得部分替換。
- **FR-015**: 對錯誤階段、不合法時限、無成功組別的標記、截止時間後的答案提交等拒絕操作，系統 MUST 提供清楚原因，且 MUST NOT 改變既有答案、成功結果、正誤標記或分數。

### Key Entities *(include if feature involves data)*

- **搶答時限**：活動在準備中設定的整數秒數；0 代表不限時，正值定義活動開始後的截止時間。
- **成功作答**：每題依既有搶答規則選出的成功組別及其已接受答案；本功能沿用此結果，不自行判斷正誤。
- **正誤標記**：老師對一題成功作答所做的「對」、「錯」或未標記判定；每題至多一個目前標記。
- **組別計分摘要**：組別編號、得分與成功題數，依指定排序構成活動計分板。
- **本組作答進度**：本組已提交的不同題目數與目前活動總題數；題組按一題計算。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 驗收案例中，0、1 及 3600 秒設定皆可接受；負數、大於 3600 或非整數設定皆被拒絕且不改變目前時限。
- **SC-002**: 在 100% 截止邊界案例中，期限前收到的有效答案依既有規則接受，期限時刻或之後收到的答案被拒絕；倒數到期在期限時自動結束搶答，手動結束則立即停止倒數。
- **SC-003**: 100% 正誤標記案例都只允許在活動結束後、且題目有成功組別時操作；標記、改標及取消後，得分均與目前標記一致，每個「對」恰得 1 分。
- **SC-004**: 100% 計分板案例均按得分、成功題數及組別編號三層排序，所有名冊組別各出現一次，且學生與老師在結束後都能查看。
- **SC-005**: 100% 搶答中學生端進度案例的 N 都等於本組已成功送出的不同題數；題組只計 1 題，無效或逾時答案不計數，其他組資料曝光數為 0。
- **SC-006**: 100% 重設案例都先呈現清除範圍並等待老師確認；確認後保留學習單與題目、清除本場作答及計分資料並回到準備中及 0 秒時限，取消時活動資料完全不變。100% 成功重新匯入案例清除舊活動作答及計分資料，匯入失敗案例保留原活動狀態。
- **SC-007**: 正常連線時，倒數及標記後的計分板更新在 1 秒內反映於連線中的師生畫面；歸零後 1 秒內所有連線畫面均顯示活動已結束。

## Assumptions

- 搶答時限採整數秒；在未開始時限為 0 的活動會顯示「不限時」。
- 活動截止依系統收到答案的時間判定；等於截止時刻的提交視為逾時，以消除倒數歸零與提交同時發生時的歧義。
- 「成功題數」指該組成為成功組別的題目數，不是所有已送出答案數；不論老師判對、判錯或取消標記，成功題數不變。題組只算一題。
- 計分板包含目前所有已設定組別；純數字組別編號按數值排序，其他識別碼按自然字串排序。
- 「重設」指老師在活動結束後使用本功能提供的操作，回到準備中並保留目前學習單及題目，以便重玩；本功能不清除或重新匯入學習單。
- 重設會先要求老師確認，且確認提示會摘要將保留與清除的資料；取消確認不產生活動狀態或資料變更。
- 只有成功完成的學習單匯入會取代活動並清除舊計分；失敗匯入不會部分改變活動。
- 活動重設及重新匯入時限預設回到 0 秒，避免新活動意外沿用前一活動的限時。
