**Feature Branch**: `codex/005-buzzer-ranking-export` (based on the approved Feature 004 PR #4 head `890395169abaede0c3d4362e630d78e8f2b4bd99`; PR #4 remains open, so Feature 005 is stacked on it)

**Created**: 2026-11-19

**Status**: Draft

**Input**: User description: "功能擴充：(1) 老師可將活動結果匯出為 CSV，至少含題號、成功組別、答案、各組搶答順位。(2) 公平順位機制：老師可選擇開啟；已搶答成功越多題的組別，其有效時間會被加上額外延遲（老師可設定），讓尚未成功的組別更有機會；預設關閉，關閉時嚴格依收到時間。(3) 結束後學生可看到完整順位。"

## Clarifications

### Session 2026-11-19

- Q: 啟用公平順位時，每組的成功題數應在何時結算，才能計算新答案的延遲？ → A: 答案被接受前，依該組在其他題目當下排行第一的題數計算，並固定該快照；後續順位變化不追溯重算。
- Q: 老師設定的延遲值，應對每一次已成功的題目累加，還是每組只加一次？ → A: 每次成功累加；成功 K 題就增加 K 倍延遲值。
- Q: 老師可設定的延遲範圍與啟用預設值為何？ → A: 以秒設定，可輸入小數；範圍為 1 到 30 秒（含端點），啟用時預填 3 秒。
- Q: 匯出的 CSV 是否要加上 UTF-8 BOM（檔案開頭的編碼標記），方便 Windows Excel 直接開啟並正確顯示繁體中文？ → A: 使用 UTF-8 並加上 BOM，方便 Excel 直接開啟。
- Q: CSV 的欄位和列代表什麼？ → A: 每筆已接受提交一列，欄位依序為題號、組別、答案、搶答順位、是否搶答成功、送出時間；未提交組別不輸出列。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 老師設定公平順位 (Priority: P1)

老師建立活動後可選擇是否啟用公平順位，並以 1 到 30 秒（含端點）設定每次已成功題數所增加的延遲，允許輸入小數；啟用時預填 3 秒。預設不啟用；若不啟用，系統完全依伺服器收到有效答案的先後排名。活動開始後設定固定，避免同一題的答案使用不同規則。

**Why this priority**: 老師必須能選擇符合課堂需要的排名方式，同時保留原本依收到時間判定的行為。

**Independent Test**: 建立活動，分別以預設關閉、啟用有效延遲及無效設定開始；確認關閉時使用收到時間、有效設定可啟用，而無效設定不會被保存或開始活動。

**Acceptance Scenarios**:

1. **Given** 老師正在準備活動且尚未開始，**When** 老師未開啟公平順位，**Then** 活動使用預設關閉設定，所有有效答案嚴格依伺服器收到順序排名。
2. **Given** 老師正在準備活動，**When** 老師開啟公平順位並設定 1 到 30 秒（含端點）的延遲（可為小數，初始值為 3 秒），**Then** 系統保存該活動的設定，並在活動開始時固定使用該設定。
3. **Given** 公平順位已啟用但延遲秒數為空、小於 1、大於 30 或非數值，**When** 老師嘗試開始活動，**Then** 系統拒絕開始並指出需設定 1 到 30 秒的延遲。
4. **Given** 活動已開始，**When** 老師嘗試更改公平順位或延遲值，**Then** 系統拒絕變更，既有排名規則及已接受答案保持不變。

### User Story 2 - 依活動規則產生每題完整順位 (Priority: P1)

學生在搶答中送出每題答案後，系統為該題所有已提交組別產生完整順位，順位第一的組別為成功組別。啟用公平順位時，已成功題數較多的組別在收到答案時會增加老師設定的秒數延遲，讓其他組別有更高機會取得較前順位；未啟用時完全依收到時間排序。

**Why this priority**: 公平延遲與每題完整順位是成功組別判定、教師檢視和活動後公布結果的共同依據。

**Independent Test**: 讓多組針對多題提交答案，其中一組先成功多題；分別以公平順位開啟及關閉兩種設定重複驗收，確認順位和成功組別符合各自規則。

**Acceptance Scenarios**:

1. **Given** 公平順位已關閉且同一題有多組有效答案，**When** 系統排名，**Then** 各組依伺服器收到有效答案的時間與確認順序排名，順位第一者為成功組別。
2. **Given** 公平順位已開啟且每次成功延遲為 D 秒，某組在答案被接受前當下於其他題排行第一 K 次，**When** 該組送出有效答案，**Then** 該答案的有效時間為伺服器收到時間加上 K×D 秒，且 K 固定為接受時的快照。
3. **Given** 同一題有多組有效答案，**When** 公平順位已開啟，**Then** 系統依各答案的有效時間由早至晚排名；順位第一者為成功組別，後續組別依序取得下一順位。
4. **Given** 兩組答案的有效時間相同，**When** 系統排名，**Then** 依伺服器確認有效提交的先後決定唯一順位，不採用用戶端時間。
5. **Given** 一組對某題尚未提交，**When** 教師檢視進行中排名，**Then** 該組顯示尚未提交且不占用數字順位；該題尚無有效提交時不顯示成功組別。

### User Story 3 - 活動結束後檢視完整順位 (Priority: P1)

活動結束後，學生可按題目查看所有組別的順位與成功組別；無提交的組別顯示未作答。學生可看到成功組別答案與自己組別答案及狀態，不會看到其他非成功組別的答案。老師可檢視完整的組別答案與順位。

**Why this priority**: 活動結束後公布完整順位，能讓全班了解每題的先後結果；沿用答案可見範圍則避免額外揭露非成功答案。

**Independent Test**: 讓不同組別提交多題答案後結束活動，分別用學生及老師身分檢視結果，確認所有組別順位可見、未作答可辨識，且答案按角色限制顯示。

**Acceptance Scenarios**:

1. **Given** 活動已結束且多組對多題提交答案，**When** 學生檢視結果，**Then** 學生可按題目看見每個已提交組別的完整順位、成功組別及未作答組別，並看見成功答案和自己組的答案與結果。
2. **Given** 活動尚在搶答中，**When** 學生查看畫面或接收更新，**Then** 學生只能看到自己組別的答案及鎖定狀態，不得看到其他組別順位、作答狀態或答案。
3. **Given** 活動已結束，**When** 學生檢視結果，**Then** 系統不顯示其他非成功組別的答案。
4. **Given** 活動已結束，**When** 老師檢視結果，**Then** 老師可看到所有組別的答案、順位、成功組別及未作答狀態。

---

### User Story 4 - 老師匯出活動順位 CSV (Priority: P1)

活動結束後，老師可下載 CSV，每筆已接受提交一列，列出題號、組別、答案、搶答順位、是否搶答成功及伺服器本機時間，方便在試算表中檢視或保存活動結果。

**Why this priority**: 可攜式結果檔讓老師能整理、分享及留存活動的順位與作答資訊。

**Independent Test**: 結束一場含多題提交的活動，匯出 CSV 並確認每筆提交各有一列、未提交組別不輸出、欄位齊全且內容符合畫面結果。

**Acceptance Scenarios**:

1. **Given** 老師已登入且活動已結束、結果已就緒，**When** 老師選擇匯出 CSV，**Then** 系統下載使用 UTF-8 加 BOM 編碼、標頭依序為 `題號,組別,答案,搶答順位,是否搶答成功,送出時間` 的檔案。
2. **Given** 活動包含多題及多組提交，**When** 老師匯出 CSV，**Then** 檔案每筆已接受提交各有一列，按題目順序及順位排列；未提交組別不輸出資料列，成功順位標示「是」、其他提交標示「否」。
3. **Given** 活動含題組答案，**When** 老師匯出 CSV，**Then** 每筆答案以 `（1）答案（2）答案` 格式依子題編號遞增排列，且題組標籤之間不加額外分隔符。
4. **Given** 使用者不是老師、活動尚未結束或結果尚未就緒，**When** 使用者要求匯出，**Then** 系統拒絕匯出並顯示明確原因，不產生不完整或誤導性的檔案。

### Edge Cases

- 公平順位未啟用時，延遲設定不得改變任何有效答案的先後或成功組別。
- 公平順位啟用但延遲秒數為空、小於 1、大於 30 或非數值時，活動不得開始；範圍內小數可接受。
- 老師設定的延遲值按每次成功逐題累加；接受答案前已成功 K 題時增加 K 倍延遲，不論成功次數多少都只增加一次的固定延遲不符合本規則。
- 已成功題數只計算該答案被接受前，該組在其他題目當下排行第一的次數；目前正在排名的題目不計入該次數。
- 每筆答案接受時記錄當時的成功題數及有效時間；後續順位更新不追溯修改已接受答案使用的延遲快照。
- 同組每題仍只有一筆有效提交；空白、重複、未知題號、無效組別或錯誤活動階段的提交不得取得順位或增加成功題數。
- 同一題多組有效時間相同時，伺服器確認提交的順序仍須產生唯一、連續順位。
- 某題無任何有效答案時，不得標示成功組別；CSV 該題不輸出資料列。
- 無提交組別顯示「未作答」，不占用順位；CSV 對應答案與順位留空。
- 結束後完整順位包含組別身分與順位，不表示公開所有組別答案；學生答案可見範圍沿用功能 003，老師可看完整答案。
- 題組的各子答案必須完整保留且依子題順序列出；單題答案行為維持既有規則。
- 伺服器收到時間相同、有效時間相同或多組同時提交時，均由伺服器確認提交順序產生唯一順位。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系統 MUST 沿用既有活動階段、老師／學生身分、組別歸屬、題目清單，以及功能 003、004 的單題與題組答案提交規則；每組每題最多接受一筆有效答案。
- **FR-002**: 僅已登入老師 MUST 能在活動「準備中」選擇是否啟用公平順位及以秒設定每次成功題數的延遲。延遲設定 MUST 允許 1 到 30 秒（含端點）的數值，並接受範圍內小數；啟用時輸入欄 MUST 預填 3 秒。公平順位 MUST 預設關閉。
- **FR-003**: 公平順位啟用時，老師 MUST 設定 1 到 30 秒（含端點）的延遲；未設定或超出範圍、非數值時，系統 MUST 拒絕開始活動並指出修正方式。若關閉時仍提供非空延遲值，也 MUST 套用相同範圍驗證。活動開始後，設定 MUST 固定至活動結束。
- **FR-004**: 系統 MUST 以伺服器收到並確認有效答案的時間作為原始時間，且 MUST 忽略用戶端提供的時間。公平順位關閉時，有效時間 MUST 等於原始收到時間。
- **FR-005**: 公平順位啟用時，系統 MUST 對每筆有效答案計算有效時間：伺服器收到時間加上「該組在此答案被接受前、於其他題目當下排行第一的題數」乘以老師設定的延遲秒數。該成功題數及有效時間 MUST 在接受該筆答案時固定；後續其他題的順位變化 MUST NOT 追溯修改已接受答案的快照。
- **FR-006**: 系統 MUST 對每題所有已接受的組別答案依有效時間由早至晚排序，產生由 1 開始且不重複的連續順位。有效時間相同時 MUST 依伺服器確認有效答案的先後決定順序；順位第一的組別 MUST 是該題成功組別。
- **FR-007**: 系統 MUST 只讓有效答案參與順位。被拒絕、空白、重複或不屬於目前活動題目的答案 MUST NOT 改變答案、順位或成功題數。
- **FR-008**: 搶答期間，已登入老師 MUST 能依題目查看各組提交狀態、已接受答案、目前順位及目前成功組別；尚未提交的組別 MUST 顯示未提交且不占用順位。
- **FR-009**: 活動搶答期間，學生 MUST 僅能得知本組提交接受／拒絕、答案與鎖定狀態；系統 MUST NOT 向學生提供其他組別的順位、作答狀態、答案或成功資訊。
- **FR-010**: 活動結束後，學生 MUST 能依題目查看所有組別的完整順位、成功組別及未作答狀態，並查看成功組別答案和本組答案／結果；學生 MUST NOT 取得其他非成功組別的答案。
- **FR-011**: 活動結束後，已登入老師 MUST 能查看每題所有組別的答案、順位、成功組別及未作答狀態。
- **FR-012**: 活動結束且結果已就緒後，已登入老師 MUST 能將活動結果匯出為 CSV；其他角色、未結束活動或結果未就緒時，系統 MUST 拒絕匯出並提供清楚原因。
- **FR-013**: CSV 標頭 MUST 依序為 `題號,組別,答案,搶答順位,是否搶答成功,送出時間`；每筆已接受提交 MUST 各有一列，包含該提交的題號、組別、答案、順位、是否成功（順位 1 為「是」，其餘為「否」）及伺服器收到時間。
- **FR-014**: CSV MUST 依活動題目順序及各題順位排列；未提交組別 MUST NOT 輸出資料列；沒有提交的題目只輸出標頭而不產生空白資料列。送出時間 MUST 使用伺服器本機時間並格式化為 `YYYY-MM-DD HH:MM:SS.mmm`。
- **FR-015**: CSV 中的單題答案 MUST 保留該組被接受的原始答案；題組答案 MUST 依子題編號遞增以 `（1）答案（2）答案` 格式連續串接，不加其他分隔符。CSV 欄位值 MUST 按 CSV 格式規則逸出，使逗號、引號或換行不會移動欄位；答案或其他資料欄位若以 `=`, `+`, `-`, `@`, 全形變體 `＝`, `＋`, `－`, `＠`、Tab、CR 或 LF 開頭 MUST 在 CSV 序列化前加上單引號，以降低試算表公式解譯風險。
- **FR-016**: 本功能 MUST 只判定提交順位與成功組別，不得判斷答案正誤或依答案計分。公平順位關閉時，系統 MUST 嚴格依伺服器收到順序排名。
- **FR-017**: 系統 MUST 以清楚訊息說明無效延遲、活動階段不符、無權限及結果未就緒等拒絕原因；拒絕操作不得改變活動設定或作答結果。
- **FR-018**: 本功能 MUST 沿用功能 003、004 的角色資料可見性與活動題目／答案結構；CSV 由老師匯出時可包含老師有權查看的各組答案，學生端不得因順位資料取得額外答案。
- **FR-019**: 匯出的 CSV MUST 使用 UTF-8 加 BOM 編碼，使繁體中文內容可在 Windows Excel 直接開啟時正確顯示，無須另外指定檔案編碼。

### Key Entities *(include if feature involves data)*

- **公平順位設定**：單一活動是否啟用公平順位，以及以秒表示、每次已成功題數所增加的延遲（允許小數秒）；活動開始後固定。
- **組別有效答案**：一組對一題的唯一有效答案、伺服器收到時間、伺服器確認順序、接受時的已成功題數快照及有效時間。
- **題目順位結果**：同一題各組已接受答案按有效時間排列的順位，以及第一順位的成功組別。
- **活動順位 CSV**：活動結束後由老師取得的提交明細；每筆已接受提交一列，包含題號、組別、答案、順位、成功狀態和伺服器本機送出時間。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 100% 公平順位關閉的驗收案例中，各組順位均嚴格依伺服器收到的有效答案先後決定，且順位第一組別與成功組別一致。
- **SC-002**: 100% 公平順位啟用的驗收案例中，各有效答案的有效時間均符合以秒設定（含正的小數秒數）的延遲值與接受時已成功題數計算規則；相同有效時間仍產生唯一、連續順位。
- **SC-003**: 100% 活動結束後學生結果頁的驗收案例中，所有組別的順位或未作答狀態均可見，且學生只取得成功答案及本組答案。
- **SC-004**: 100% CSV 驗收案例中，每筆已接受提交各有一列、未提交組別沒有列、六欄位與結果頁相符，題組子答案連續依序排列，成功狀態和本機送出時間正確；逗號、引號及換行答案可正確逸出，公式觸發前綴會加單引號，繁體中文可在 Windows Excel 直接開啟時正確顯示。
- **SC-005**: 100% 非老師、活動未結束、結果未就緒或延遲設定無效的案例中，系統拒絕不允許的操作，且不改變設定、答案、順位或成功組別。
- **SC-006**: 在正常本機連線下，以本活動 `GROUP_IDS` 設定的組數 N 作為驗收負載（每組一條學生 WebSocket 連線），每筆有效答案送出後，老師 MUST 在 2 秒內看到該題更新後的順位及成功組別；驗收記錄 MUST 包含 N 與量測結果。
- **SC-007**: 100% 角色可見性驗收案例符合規則：進行中學生只看到本組進度，活動結束後學生能看到完整順位而不能看到其他非成功組別答案，老師能查看完整結果。

## Assumptions

- 本功能沿用 001 的老師／學生角色、組別及三個活動階段，沿用 003 的一組每題一次有效答案、伺服器時間判定、錯誤處理及學生答案可見性，並沿用 004 的題組答案結構。
- 老師於活動「準備中」設定公平順位；活動開始時設定固定，以免不同答案套用不同規則。公平順位預設關閉；啟用後延遲欄預填 3 秒，可設定 1 到 30 秒（含端點）並可輸入範圍內小數。
- 「已成功題數」按答案被伺服器接受前，該組在其他題目當下排行第一的題數計算；不計算正在提交的題目。此數值於答案接受時固定，避免後續即時排名變化追溯影響已接受答案的有效時間。
- 同一題的順位只涵蓋已提交有效答案的組別；尚未作答組別顯示未提交／未作答且不占數字順位。
- 活動後「完整順位」表示每題所有組別的排名及未作答狀態，不代表公開所有組別答案；非成功組別答案仍遵循功能 003 的學生端限制。
- CSV 每列代表一筆已接受的題目／組別提交；未提交組別不輸出列。題組答案依子題編號遞增連續組成同一 CSV 欄位文字；資料欄以單引號前綴中和公式觸發字元，再按 CSV 規則逸出逗號、引號和換行；送出時間使用伺服器本機時間。
- CSV 使用 UTF-8 加 BOM，方便 Windows Excel 直接辨識繁體中文；匯出不改變活動資料，也不新增成績或答案正確性判斷。
- 活動結果沿用既有單一本機活動生命週期；伺服器程序重啟後的活動復原不屬於本功能範圍。
